0. 문서 관리 규칙

원본·판 찍기·생성·검사

  • 원본: report/editions.json(판 기록)과 report/meta.json, 생성기 scripts/gen-report.mjs. 판 기록의 숫자는 판을 찍을 때 기계가 잰 값이고, 사람이 쓰는 것은 판마다의 소견(note)뿐이다.
  • 판 찍기: npm run docs:spec이 명세를 만든 뒤 명세 판이 직전 TR 판과 다르면 시험을 돌리고 판을 하나 더한다. 명세가 그대로여도 판을 찍으려면 npm run docs:report -- --force.
  • 생성: HTML은 판 기록만으로 그린다. 그래서 같은 판 기록이면 언제 만들어도 같은 HTML이다 — 지난 판의 숫자를 지금 다시 재지 않는다.
  • 검사: npm test가 HTML이 판 기록과 맞는지, 마지막 판이 지금 명세 판을 반영하는지 본다. 명세만 고치고 판을 안 찍으면 실패한다.

읽는 법

  • 시험 결과는 판을 찍은 그 순간 npm test와 같은 조건으로 돌린 값이다. 실패도 그대로 남긴다. 단 'TR 마지막 판이 지금 명세 판을 싣고 있다' 검사 1건은 그 판을 만드는 중이라 건너뜀으로 잡힌다.
  • 기준 커밋은 판을 찍을 때의 HEAD다. 명세를 고치고 커밋하기 전에 찍는 경우가 많아, 그때는 '커밋 전 변경 있음'을 함께 적는다.
  • 행동 평가는 실제 모델을 불러 돈이 들기 때문에 판마다 다시 돌리지 않는다. 판에는 그때까지의 마지막 평가 결과가 실린다.
  • 로그 감사의 후보 수는 판마다 지금 로그로 다시 센다. 확정 수는 사람이 판정한 값이라, 판정 범위 이후의 후보는 '판정 대기'로 따로 센다.

배포·보관

  • 커밋: 판 기록과 HTML을 명세와 함께 커밋한다. 지난 판은 지우지 않는다.
  • 공개: 명세와 같은 경로로 운영 정보를 가린 사본이 QA-Justice/tiatya-bridge-docs의 tr.html로 PR에 실린다. 머지는 사람이 한다.
